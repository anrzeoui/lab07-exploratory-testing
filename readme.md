## 5. Дүгнэлт (9 өгүүлбэр)

Энэхүү ажлаар номын жагсаалт вэб аппын найман ялгаатай согогийг UI болон API шалгалтаар баталгаажуулсан. Couch Potato аяллын хүрээнд хоосон талбар болон хүчингүй онтой ном үүсэж байгаа нь оролтын validation дутуу байгааг харуулсан. Fed-Ex аргачлалаар давхардсан ном болон «Нийт ном» тоолуурын өгөгдлийн зөрүүг илрүүлсэн. Supermodel аяллын үед хайлт том, жижиг үсэг ялгах болон устгах үйлдлийн дараа тохироогүй мессеж гарах асуудлууд ажиглагдсан. Saboteur аяллаар `/old` хуудасны HTTP 500 болон malformed JSON хүсэлтэд HTTP 200 буцаах API согогийг шалгасан. Эдгээрээс Couch Potato нь заавал бөглөх талбарын бизнесийн дүрмийг, Saboteur нь интерфейсийн доод түвшний семантикийг тодорхой болгоход үр дүнтэй байв. Хүчингүй он, давхардал, хайлт, тоолуур, HTTP статусын согогуудыг Playwright-ийн автомат регрессийн тестээр цаашид илрүүлж болно. Харин буруу мэдэгдлийн ойлгомжтой байдал, өнгө болон урт тексттэй хүснэгтийн ашиглахад хялбар байдлыг хүний нүдээр нэмж үнэлэх шаардлагатай. Дараагийн exploratory session-д урт оролт, боломжгүй өгөгдлийн төрлүүд, хүртээмж болон олон хэрэглэгч зэрэг ажиллах нөхцөлийг судлах нь зүйтэй.
